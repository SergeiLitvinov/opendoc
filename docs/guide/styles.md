# Свойства и эффективный стиль

OpenDoc Model сохраняет заданные стили и отдельно вычисляет их эффективные значения.
Разрешение стиля не меняет документ, не материализует свойства в каждом run и не
добавляет историю преобразований. Исполняемый сценарий — `examples/styles.py`.

## Строгое чтение и запись свойств

Все типизированные bags — `SectionProperties`, `ParagraphProperties`,
`TextStyleProperties`, `ImageProperties`, `TableProperties`, `TableRowProperties`,
`TableCellProperties` — предоставляют методы:

```python
properties.get_typed(key, *, limits=None)
properties.set_typed(key, value, *, limits=None)
```

Известны поля существующих публичных accessors, включая унаследованные поля
`ParagraphProperties` в `TextStyleProperties`. Неизвестное имя даёт `ValueError`;
расширения читают и записывают обычным `properties[key]`. Другие ключи при строгой
операции сохраняются. Отсутствующее поле и явный `None` читаются как `None`, в том
числе для контейнеров. Запись `None` сохраняет ключ; `del properties[key]` удаляет его.

| Тип поля | Допустимые значения и нормализация |
| --- | --- |
| `str` | Только строка, включая пустую; автоматического `str(object)` нет |
| `bool` | Булево, целые 0/1, строки `0/false/off/no` и `1/true/on/yes` без учёта регистра и внешних пробелов |
| `int` | Целое без bool либо десятичная ASCII-строка с необязательным знаком и внешними пробелами; дроби не усекаются |
| `float` | Конечное число без bool либо строка, преобразуемая в конечное число |
| `list[int]`, `list[str]` | Именно список; элементы преобразуются по тем же правилам |
| `dict[str, int]` | Именно словарь с текстовыми ключами и целыми значениями по тем же правилам |
| `WrapPolygon` | JSON-словарь с `edited: bool` и `points: list` словарей с целыми `x`, `y` без bool; дополнительные поля сохраняются |

Ошибка преобразования даёт `ValueError` с именем схемы, ключом и расположением
элемента контейнера. Чтение не нормализует хранимое значение. Запись сначала
проверяет и преобразует значение, затем присваивает его; отказ оставляет bag
нетронутым. Контейнеры результата и записанные контейнеры независимы от входа.
Значение проходит JSON-проверку с [DocumentLimits](limits.md), включая циклы,
глубину, число значений и объём текста. Превышение даёт `ArtifactLimitError`.
Ограничения применяются к одному значению; они не валидируют прочие поля bag.

Это преобразование типов, а не проверка предметных диапазонов или ссылок.
Например, существование `base_style_id` проверяет модель/разрешение стиля;
`set_typed` принимает любую строку. `WrapPolygon` координаты задаются целыми,
дополнительные поля не получают неявной семантики.

Совместимость: прежние read-only accessors, конструкторы и mapping-запись
сохраняют поведение. Старые getters могут преобразовать произвольное значение
в строку, применить `bool(value)`, усечь дробь через `int` или вернуть пустой
контейнер при неподходящем типе; numeric getters сохраняют исключения Python.
Для контролируемых данных используйте новые методы. JSON продолжает сохранять
сырые допустимые значения bags без автоматического преобразования известных полей.

## Разрешение стиля

```python
resolve_style(document, style=None, *, overrides=None, limits=None)
effective_text_style(document, paragraph, run=None, *, limits=None)
```

Обе функции экспортированы из `opendoc_model` и возвращают независимый `TextStyle`.
`resolve_style` принимает ID из `document.styles`, самостоятельный `TextStyle`
или `None`. Сначала разрешается цепочка `base_style_id` до корня, затем значения
накладываются от корня к потомку. `overrides`, если задан, должен быть `TextStyle`;
его собственная цепочка разрешается отдельно и накладывается последней.

`None` в поле или property означает наследование. `False`, `0`, пустая строка,
пустой список или словарь — явное переопределение. Отсутствующий property ведёт
себя как `None`. Если нигде нет значения, поле остаётся `None`, а property не
появляется в результате. Эти правила относятся и к неизвестным JSON-свойствам.
Значения свойств накладываются по ключу: вложенный словарь/список заменяется
целиком, без глубокого слияния. `base_style_id` является управляющей ссылкой,
потребляется при разрешении и отсутствует в результате. Другие properties,
включая `numbering_source_style_id`, сохраняются как данные и не создают
дополнительного наследования. Значение `None` не является командой сброса;
неявных шрифта, размера, цвета и прочих defaults рендерера нет.

`effective_text_style` накладывает разрешённый `paragraph.style_id`, затем
ненулевые в смысле `is not None` свойства абзаца, затем разрешённый inline-стиль
заданного run. Свободный `base_style_id` в properties абзаца не создаёт цепочку.
Геометрия и `paragraph.alignment` остаются полями абзаца, не превращаются в поля
`TextStyle`. Без run возвращается стиль абзаца; run должен находиться в
`paragraph.content` по идентичности объекта. Сам абзац может быть вне документа:
его ссылки проверяются относительно стилей и ресурсов переданного документа.
Табличный стиль автоматически не применяется к содержимому ячеек; его ID
можно отдельно передать в `resolve_style`.

Перед операцией проверяется весь исходный документ, включая неиспользованные
стили, ресурсы и пакет. Для самостоятельного inline/абзаца проверяется также
его контекст. Отсутствующие ссылки, неверные типы и циклы дают `ValueError`.
Цепочка обрабатывается итеративно, без ограничения глубиной рекурсии Python.
`limits` ограничивает исходную модель, отдельный контекст и результирующий стиль;
размер JSON для сериализации проверяется отдельно при сохранении.
Мутируемые значения результата скопированы; внутренние общие объекты внутри
результата могут сохранять общую идентичность. Источник и override не меняются.
