# Списки и нумерация

`ListItem(list_id, level=0, kind="ordered", start=1, restart=None)` задаёт принадлежность абзаца к списку независимо от текста и оформления. Непустой ID объединяет элементы в последовательность; отдельный реестр списков не нужен. Уровни — целые числа от 0 до 8, начальный номер и перезапуск — положительные целые числа. `bool` не принимается вместо числа. Для `kind="unordered"` допускаются только `start=1` и `restart=None`.

`set_list_item(paragraph, item)` устанавливает роль, `get_list_item(paragraph)` читает её, а `set_list_item(paragraph, None)` удаляет. Изменение проверяется до записи и сохраняет неизвестные поля распознанного расширения. `iter_list_items(document)` возвращает положения абзацев во всех семи коллекциях секции и вложенных таблицах. Повторные вхождения одного объекта учитываются отдельно.

`iter_list_numbers(document)` возвращает `ListNumber(location, item, number)`. Для маркированного элемента номер равен `None`. Для нумерованного элемента счётчик каждого уровня начинается с `start`, увеличивается при следующем вхождении и может быть явно изменён через `restart`. Более низкий по вложенности уровень сбрасывает более глубокие счётчики этого списка, включая случай маркированного родителя. Разные ID имеют независимые счётчики; обычный абзац не прерывает последовательность. Один ID продолжает последовательность между секциями и колонтитулами: для независимых последовательностей назначайте разные ID.

На одном уровне одного ID значения `kind` и `start` должны совпадать. Вся последовательность проверяется до выдачи первого номера. Уровень без родителя допустим. Результат содержит номер текущего уровня; составная метка, вид маркера и оформление принадлежат потребителю. Положение ссылается на живой абзац, роль и номер фиксируются на момент расчёта. После изменения структуры рассчитывайте номера заново.

## Сохранение и композиция

Роль хранится в `Paragraph.properties["opendoc.list-item"]` как JSON-объект с `format="opendoc.list-item"`, `version=1`, обязательным `list_id` и необязательными полями конструктора с указанными выше значениями по умолчанию. Это совместимое расширение свойств: версия документа остаётся 2, чтение поддерживает 1 и 2, версия схемы свойств остаётся 1. Прежние читатели сохраняют неизвестное свойство. Неподдержанная версия объявленного расширения отклоняется; произвольное значение без этого маркера остаётся непрозрачным и не перезаписывается setter-ом. Старые свободные свойства нумерации автоматически не мигрируют.

`merge_documents` проверяет конфликты ID списков наряду со стилями и ресурсами. По умолчанию конфликт отклоняется; `conflicts="rename"` переименовывает группы с учётом всех исходных ID и возвращает карту `DocumentIdMap.lists`. Прежний конструктор карты с двумя аргументами сохраняется. `extract_document` сохраняет принадлежность; номер пересчитывается для полученной последовательности. Для фиксированного исходного номера задайте `restart` явно.

## Проверка и сравнение

Инспекция абзаца содержит `list_item` и вычисленный `list_number`, счётчики `semantic_list_items` и `ordered_list_items` считают новые роли. Прежний `numbered_paragraphs` продолжает учитывать старое свойство `numbering_id`.

Сравнение возвращает `lists_available`, `changed_list_items`, `list_numbers_available`, `changed_list_numbers`. Старые или повреждённые инвентари не объявляются известными: соответствующие счётчики равны `None`. Снятие роли даёт `LOSS` с кодом `list-loss`, изменение роли — `WARNING/list-change`, изменение только вычисленного номера — `WARNING/list-number-change`. Общая политика качества может запрещать потери; объектная политика сама по себе не проверяет роли списков.

Исполняемый пример: [examples/lists.py](../../examples/lists.py).
