# OpenDoc — развитие библиотеки

Цель — самодостаточная Python-библиотека: создать документ, обойти и изменить его структуру, управлять свойствами и ресурсами, сохранить, восстановить и проверить изменения через понятный публичный API. Для этого не требуется редактор или конкретное приложение-потребитель.

В план входят модель, её расширение, сериализация, валидация, сравнение, документация, тесты и выпуск пакета. UI, сеансы редактора, undo/redo, хранение прикладных задач, Web/CLI для пользователей, импорт/экспорт офисных файлов и миграции прежних форматов приложений ведутся в отдельных проектах. Инструменты сборки и документации относятся к поддержке библиотеки.

Исходная точка — [текущее руководство](docs/guide/index.md) и [навигатор кода](docs/reference/code.md). Уже реализованные возможности не являются задачами. Статус отмечен флажками; порядок оставшихся задач задают приоритеты P0–P3. Новую задачу можно принять по самостоятельному библиотечному сценарию и критерию готовности, без привязки к будущему редактору.

## P0. Надёжность ядра и совместимость

- [x] **L01. Совместимость API и схем.** [Правила совместимости](docs/guide/compatibility.md) определяют версии пакета/JSON/свойств, границу публичного API, исключения и порядок устаревания. Сохранённый контракт API и независимые JSON-фикстуры v1/v2 проверяются в `tests/test_compatibility.py`; изменение контракта требует явного решения и регрессионного сценария.

- [x] **L02. Предсказуемые ошибки JSON.** Кодек проверяет контейнеры, обязательные поля, enum, целочисленные версии, base64, идентификаторы и допустимые JSON-расширения до создания объектов. Неверные поля дают `ValueError` с расположением; допустимые неизвестные ключи сохраняются. [Правила JSON](docs/guide/json.md) и `tests/test_document_json.py` описывают и проверяют ошибки чтения/записи.

- [x] **L03. Лимиты чтения и сложности модели.** [DocumentLimits](docs/guide/limits.md) задаёт байты, глубину, число значений и общий объём ресурсов/частей пакета. Чтение ограничено бюджетом плюс одним байтом, встроенные данные проверяются до декодирования, циклы — до рекурсивной сериализации. Запись частями остаётся атомарной. `tests/test_document_limits.py` проверяет точные границы, циклы, большое вложение и сохранность прежнего файла.

- [x] **L04. Структурная валидация.** [Общие правила](docs/guide/validation.md) применяются к модели в памяти, чтению, записи и инспекции: типы элементов, ссылки/наследование стилей, ключи ресурсов, span, конечная геометрия, обрезка и топология пакета. `tests/test_model_validation.py` проверяет одинаковые нарушения в памяти/JSON, вложенные таблицы и все семь коллекций секции. Инспекция повреждённой структуры возвращает ошибки с расположением и неизвестные метрики; предупреждения допустимой модели остаются отдельными.

- [x] **L05. Полнота сериализации.** Матрица `tests/test_document_roundtrip.py` проверяет два цикла через словарь, JSON и файл для v1/v2 и трёх режимов. Сохраняются все блоки/inline, семь коллекций секции, стили/цвета, геометрия/crop, формулы, provenance/surrogate, пустые байты, внешние источники и непрозрачные части/связи пакета. Полная модель сравнивается с исходной, включая вложенные свойства; чтение v1 даёт v2 без прикладных миграций и без открытия внешних источников.

- [x] **L06. Контракты сравнения и политик качества.** [Правила измерений и допусков](docs/guide/quality.md) закреплены в `tests/test_quality_contracts.py` и `tests/test_object_matching.py`: все политики, пустая модель, пороги, дубликаты, перестановки, эвристики и бюджеты слов/выделений. Неизвестные метрики/хеши не объявляются нулями или доказанной потерей, строгие допуски отклоняют недоступность. Проверены геометрия до округления, шрифты/aliases, кратность ресурсов/частей пакета и независимый эталон расстояния слов.

- [x] **L07. Optional math и границы XML.** [Контракт формул](docs/guide/formulas.md) описывает подмножество MathML/OMML и недоступность без `math`. `tests/test_mathml.py` проверяет независимые ожидаемые деревья, конструкции, неизвестные атрибуты/namespace; `tests/test_formula_xml.py` — Unicode/XML, DTD/сущности, запрет внешнего разрешения и точные пределы 1 МиБ, 4096 элементов, глубины 64. Общий разбор ограничивает исходник; OMML не отбрасывает значимый текст или данные обёртки. Проверка wheel подтверждает LaTeX и строгую недоступность XML в пустом окружении без `lxml`.

## P1. Удобный самостоятельный API

- [x] **L08. Единый API обхода и поиска.** [Публичные итераторы](docs/guide/traversal.md) находят секции, блоки, inline, выбранные типы и ресурсные ссылки во вложенных таблицах и всех семи коллекциях секции. `NodeLocation` содержит реального родителя, поле, индекс и относительный путь каждого вхождения; описаны порядок и обновление путей после структурных правок. Валидация, инспекция и инвентаризация используют общий обход; fallback/surrogate учитываются как использования ресурсов. `tests/test_traversal.py` проверяет точные пути, повторные вхождения, поддеревья, фильтры, ссылки, бюджеты и сохранение порядка текстового потока; исполняемый пример и независимый wheel подтверждают поиск и изменение без пользовательской рекурсии.

- [x] **L09. Операции над структурой.** [Модуль операций](docs/guide/operations.md) копирует документ/поддерево со всеми изменяемыми данными, предоставляет вставку/замену/удаление по расположению, ограниченное UTF-8-извлечение текста и преобразование выбранных вхождений на независимой копии. Описаны мутация, порядок обработчиков, внутренние общие объекты, актуальность путей и сохранение provenance без скрытой истории редактора. `tests/test_operations.py` проверяет вложенные свойства/ресурсы/пакет, все структурные позиции, откат при превышении бюджета, ошибки обработчиков, точные текстовые границы и сохранность оригинала. `examples/operations.py` и независимый wheel выполняют сценарий копирования, изменения выбранного текста, валидации и сохранения/чтения.

- [x] **L10. Объединение и извлечение с зависимостями.** [Композиция документов](docs/guide/composition.md) объединяет секции с явным отказом/переименованием конфликтующих ID и картами для каждого входа, переписывает поддержанные ссылки на стили/ресурсы без повторного изменения общих объектов. Извлечение секции, блока, inline, строки или ячейки сохраняет контекст и транзитивные зависимости; зависимости расширений можно указать явно. Описаны решения для метаданных, режимов и непрозрачных пакетов, суммарные входные бюджеты. `tests/test_composition.py` проверяет точные карты/значения ссылок, колонтитулы, оболочки, provenance, пакеты, независимость и сохранение/чтение JSON; исполняемый пример и независимый wheel подтверждают самостоятельные сценарии.

- [x] **L11. Свойства и эффективный стиль.** [Строгие операции и разрешение стилей](docs/guide/styles.md) предоставляют `get_typed`/`set_typed` для известных полей всех bags, сохраняя прежние getters и mapping API расширений. Описаны преобразования, расположение ошибок, атомарность, независимые контейнеры и бюджеты. `resolve_style` и `effective_text_style` разрешают `base_style_id`, проверяют ссылки/циклы и возвращают независимый результат; `None` наследует, явные `False`, ноль и пустые значения переопределяют. `tests/test_properties.py` и `tests/test_styles.py` проверяют правила, ошибки, сохранность, длинную цепочку и JSON. Исполняемый пример и установленный wheel без зависимостей подтверждают самостоятельный сценарий.

- [x] **L12. Согласованные операции с ресурсами.** [Управление ресурсами](docs/guide/resources.md) предоставляет добавление с `error`/`rename`/`replace`, поиск использований, замещение определения, удаление с явным перенаправлением ссылок и поиск точно одинаковых встроенных байтов. Общая грамматика учитывает изображения, fallback, surrogate и стандартную ссылку TextRun во всех коллекциях; отказ восстанавливает ссылки и сохраняет идентичность узлов. `embed_resources` создаёт независимую копию с ограниченным чтением локальных файлов, явным абсолютным каталогом для относительных источников и общим бюджетом ресурсов/пакета. JSON не открывает внешние источники. `tests/test_resources.py`, исполняемый пример и wheel без зависимостей проверяют политики, ошибки, общие объекты, пути, пустые данные, границы чтения и переносимость.

- [x] **L13. Диагностика модели в памяти.** [Проверка и сравнение](docs/guide/checks.md) возвращают `CheckResult` без выходного пути, со структурированными `DiagnosticIssue`: код, severity, точное расположение, измерение и причина. Валидация передаёт путь от источника обнаружения, без разбора сообщений; старые строковые ошибки и отчёты поддержаны. Все политики принимают оба результата и сохраняют причины отказа/недоступности; результат сериализуется как самостоятельный `opendoc.check` v1. Проверка не обращается к внешним файлам, неизвестные байты остаются `None`, решение о публикации принадлежит потребителю. `tests/test_checks.py`, исполняемый пример и wheel без зависимостей проверяют коды, стороны сравнения, снимки, все политики, бюджеты, сериализацию и отсутствие файловых обращений.

## P2. Расширение модели и масштабирование

- [x] **L14. Семантические элементы.** [Заголовки](docs/guide/headings.md), [списки/нумерация](docs/guide/lists.md), [внутренние ссылки/якоря](docs/guide/references.md) и [богатые сноски](docs/guide/footnotes.md) имеют явные структуры, создание/изменение, валидацию, обход и сравнение. Композиция переписывает ID и замыкает зависимости. Собственные tagged-схемы v1 сохраняют JSON документа v2, чтение v1/v2 и bags v1; старый reader сохраняет данные в metadata/properties. Регрессионные сценарии, сохранённый API, исполняемые примеры и wheel без зависимостей проверяют самостоятельное создание, изменение, сохранение/чтение и сравнение без импортёра офисного формата.

- [ ] **L15. Уточнить контракт расширений и непрозрачных пакетов.** Определить пространства имён пользовательских свойств/метаданных, способ подключения их валидаторов и границы поддерживаемых типов элементов. Для `PackageGraph` описать форматонезависимый контракт корня, имён и связей и совместимый переход от неявных DOCX-значений по умолчанию. Готово, когда расширения проходят сериализацию без потери данных, явно заданный пакет произвольного формата восстанавливается без прикладных предположений, а неизвестные типы/версии не принимаются молча.

- [ ] **L16. Измерить и ограничить стоимость больших документов.** Добавить воспроизводимые измерения обхода, JSON/base64, вложенных таблиц и сопоставления множества одинаковых объектов. В [сопоставлении](src/opendoc/object_matching.py) проверить стоимость повторного поиска кандидатов; в инспекции — повторного вычисления содержимого таблиц. Готово, когда опубликованы размеры входов и затраты времени/памяти, устранены подтверждённые лишние обходы, а превышение введённых вычислительных бюджетов даёт явную недоступность измерения с сохранением семантики дубликатов.

## P3. Поддержка и выпуск библиотеки

- [ ] **L17. Проверять заявленную типизацию.** Подключить статическую проверку типов производственных модулей и небольшого сценария потребителя установленного `py.typed`-пакета. Разобрать `Any` вне обоснованных JSON/XML-границ и определить типы результатов инспекции/сравнения. Готово, когда выбранный typecheck выполняется в CI и проверяет использование публичного API, а документация отличает аннотации от статически проверенных контрактов.

- [ ] **L18. Усилить проверки независимости.** Сделать [архитектурный тест](tests/test_architecture.py) рекурсивным для будущих подпакетов, проверять ленивую загрузку `lxml`, добавить прогон основных сценариев без extra `math`. Расширить [проверку wheel](tools/check_wheel.py) сценариями формул и строгой недоступности XML-проверки. Готово, когда основная модель, изменение структуры, JSON и сравнение работают в пустом окружении только с OpenDoc, а установка extras добавляет лишь заявленные возможности.

- [ ] **L19. Подготовить воспроизводимый выпуск.** Добавить файл заявленной лицензии MIT с корректными данными правообладателя, проверить метаданные дистрибутива и единый источник версии пакета. Проверять сборку/установку из sdist и wheel, состав архивов и совпадение версий в метаданных и `opendoc.__version__`. Готово, когда CI воспроизводит установку без исходного checkout, артефакты не включают окружения/кэши/прикладные файлы, а изменения поведения отражены в заметках выпуска. Публикация пакета — отдельное действие после подготовки выпуска.

- [ ] **L20. Расширить руководство исполняемыми сценариями.** Добавлять в [руководство](docs/guide/index.md) примеры ресурсов, свойств, вложенных таблиц, всех колонтитулов, диагностики, политик качества и optional math; по мере реализации — обхода, преобразований и объединения. Готово, когда проверка документации запускает примеры, показывает ограничения и ошибки, а справочник API и навигатор генерируются автоматически. Будущие возможности остаются в TODO до реализации.

## Приёмка каждой задачи

Закрывать пункт после реализации, проверки его критерия и обновления описания текущего поведения в `docs/guide/`. Сохранять самостоятельность пакета, публичную совместимость и версионирование собственных схем. При несовместимом изменении сначала выполнить правила L01.

Проверки выполнять по [стандартам](CODING_STANDARDS.md): `uv sync --all-extras` → `uv run ruff check` → `uv run ruff format --check` → `uv run pytest`; справочники обновлять через `uv run python -m tools.docs generate`, затем выполнять `uv run python -m tools.docs check`. Собранный wheel проверять в пустом окружении через `tools/check_wheel.py`. Генерируемые рабочие файлы хранить в `.opendoc/`.
